# الأثيل — تطبيق أندرويد

تطبيق عربي لإدارة إسطبل الأثيل، بتصميم فحمي وذهبي، ولوحة معلومات بعد الدخول. مبني من مراجعة إجراءات مستودع [Aheer_Stable](https://github.com/amjadoh/Aheer_Stable/tree/179056e2eccd164e1d37e075618ec802a07aba43). المنصة المطلوبة **أندرويد فقط**. أيقونة التطبيق وشاشة البدء تستخدمان شعار الإسطبل الأصلي الموجود في `public/logo.jpeg`.

## التجربة على أندرويد

من تبويب **Actions → Android APK → آخر تشغيل ناجح → Artifacts** حمّل `Alatheel-Android-demo`، ثم فك الملف وثبّت `app-debug.apk` على جهاز أندرويد 7 أو أحدث. الحزمة للتجربة المحلية، وتحتوي أدوار مدير وموظف ومالك وعضو. جميع بياناتها تجريبية وتحفظ على الجهاز؛ يمكن إعادة ضبطها من «حسابي / المزيد».

**النسخة المتصلة:** الكود يتضمن دخول Google وخدمات Firebase، لكنه يحتاج إعداد مشروع Firebase ونشر الخدمات والقواعد وإضافة ملف أندرويد الخاص بالمشروع. إنشاء هذا المستودع لا ينشر الخدمات ولا ينقل بيانات الإسطبل تلقائيًا. وضع التجربة منفصل تمامًا عن Firebase. لا يظهر تبديل الأدوار عند بناء النسخة المتصلة.

## الإجراءات المنفذة

- شاشة قبل الدخول: صورة خيل توضيحية، خدمات الإسطبل، التسجيل والدخول.
- داشبورد حسب الصلاحية: الخيل، الملاك، التحصيل، الطلبات، التكلفة التقديرية، التنبيهات، تقارير Excel وPDF.
- الخيل: إضافة، تعديل، برنامج تغذية، ملف وQR، إخراج بسبب وتاريخ، أرشيف واستعادة.
- التسجيل: طلب باسم الخيل وعمره ونوع الخدمة ورقم التسجيل والملاحظات؛ مراجعة الإدارة وتسعير أو رفض؛ موافقة المالك تسجل الخيل وموعد استحقاقه في عملية واحدة.
- المخزون: أصناف ووحدات وأسعار وحد تنبيه، إضافة وصرف مع سبب وسجل حركة؛ يمنع الرصيد السالب وحذف صنف مستخدم أو ذي رصيد.
- المصروفات: إضافة وتعديل، تكرار، ربط بخيل أو مصروف عام؛ المدير يحذف المصروف غير المحصل.
- التحصيل: رسوم الإيواء وحصة المصروفات لمرة واحدة، تأكيد الاستلام، سجل التحصيل، وترحيل الاستحقاق شهرًا من موعده السابق؛ يدعم الإيواء والتشبيه.
- الأعضاء: المدير ينشئ مالكًا أو موظفًا بالبريد والاسم والجوال، ويغير الصلاحية إلى مدير/موظف/مالك/مشاهد، ويعطل أو يفعل أو يحذف. يمنع حذف صاحب خيل نشطة وتغيير المدير لحسابه من نفس الشاشة.
- الملف الشخصي وبيانات الإسطبل وسجل العمليات.

## الصلاحيات

| الإجراء | مدير | موظف | مالك / عضو |
|---|---|---|---|
| تشغيل الخيل والمخزون والتحصيل | نعم | نعم | قراءة سجلاته فقط |
| مراجعة طلبات الخيل وتسعيرها | نعم | نعم | تقديم طلبه والموافقة على عرضه |
| إضافة وتعديل مصروف | نعم | نعم | لا |
| حذف مصروف غير محصل | نعم | لا | لا |
| إدارة الأعضاء والصلاحيات | نعم | لا | لا |
| تغيير بيانات حسابه | نعم | نعم | نعم |

الصلاحيات مفروضة على الخادم وقواعد قاعدة البيانات. جميع الكتابات تمر عبر الخدمات. الحساب الجديد يبدأ «مشاهدًا»، ولا يمكن اختيار صلاحية مدير في التسجيل العام.

## التشغيل المحلي

يتطلب Node 22 أو أحدث وpnpm 11.25.0.

```sh
pnpm install --frozen-lockfile
cp .env.example .env
pnpm dev
pnpm test
pnpm build
pnpm --dir functions build
```

في Windows استخدم `Copy-Item .env.example .env` بدل `cp` إذا لزم. `.env.example` يبدأ بوضع تجربة صريح. في غياب الإعدادات لا يتصل التطبيق تلقائيًا بأي مشروع ولا يختار التجربة دون إعدادها.

## إعداد النسخة المتصلة

1. أنشئ أو اختر مشروع Firebase تجريبيًا. فعّل Firestore وGoogle ضمن Authentication. تستخدم Cloud Functions الجيل الثاني وتتطلب خطة تدعمها.
2. أضف تطبيق Android باسم الحزمة `com.alatheel.stable`. أضف بصمة SHA-1 لشهادة البناء. ضع ملف المشروع في `android/app/google-services.json`؛ الملف مستثنى من Git.
3. ضع إعدادات تطبيق Firebase للويب في `.env`، واجعل `VITE_DEMO_MODE=false`. اضبط `VITE_FIREBASE_DATABASE_ID` و`FIRESTORE_DATABASE_ID` للخادم على نفس قاعدة البيانات عند استخدام قاعدة مسماة؛ الافتراضي `(default)`. منطقة الخادم والعميل يجب أن تتطابق.
4. بعد الدخول عبر Google، ينشأ ملف عضو. لإنشاء أول مدير، نفذ السكربت أدناه باستخدام بيانات اعتماد مالك المشروع في بيئة موثوقة. السكربت لا يحتوي قائمة بريد ثابتة ولا مفاتيح:

```sh
cd functions
node scripts/bootstrap-admin.cjs your-verified-google-email@example.com
```

5. انشر القواعد والخدمات عبر Firebase CLI بعد تحديد المشروع المقصود:

```sh
firebase use YOUR_PROJECT_ID
pnpm --dir functions build
firebase deploy --only firestore:rules,firestore:indexes,functions
```

6. ابن التطبيق المتصل ثم انسخ موارده لأندرويد. يجب تمرير `VITE_DEMO_MODE=false` أيضًا لأمر Capacitor؛ ملف إعداد Capacitor يقرأ متغير العملية، لتضمين إضافة Google الأصلية فقط في البناء المتصل.

```powershell
$env:VITE_DEMO_MODE='false'
pnpm build
pnpm exec cap sync android
pnpm android
```

يتطلب بناء أندرويد JDK 21 وAndroid SDK 36. للبناء التجريبي اجعل المتغير `true`. Google Sign-In الأصلي لا يعمل دون ملف المشروع وبصمات التوقيع الصحيحة. لا تضف مفاتيح الخدمة أو التوقيع إلى المستودع. إعدادات نسخة المتجر وتوقيعها تتم من Android Studio.

## سلامة العمليات وحدود الإصدار

- اعتماد الطلب وحركة المخزون والتحصيل تحفظ داخل معاملة واحدة. لكل عملية معرف لمنع تكرارها عند إعادة الإرسال؛ التحصيل يتحقق أيضًا من دورة الاستحقاق والمبلغ اللذين رآهما الموظف.
- حصة المصروف المشترك ثابتة، وتحسب بالهللات دون فقد فروق التقريب. لا يتغير أصل المصروف عند تحصيل أحد الخيل ولا يمكن تعديل مصروف مرتبط بتحصيل سابق.
- حذف العضو يحذف حساب Firebase Auth ويحتفظ بسجل معطل مخفي من الواجهة لحماية روابط التاريخ المالي. التعطيل يمنع الكتابة وقراءة السجلات حتى لو بقيت جلسة قديمة.
- إنشاء العضو يستخدم معرف Firebase Auth نفسه، ويمكنه الدخول بحساب Google الموافق للبريد؛ لا يولد التطبيق كلمات مرور ولا يرسل بريدًا نيابة عن الإدارة.
- الخدمات تقرأ فقط المجموعات اللازمة للعملية، بحد 4000 سجل لكل مجموعة، وترفض بوضوح تجاوز الحد. قبل التوسع، تحول الاستعلامات إلى قراءة السجلات المرتبطة وحدها وتضاف صفحات للقوائم. هذا الإصدار مناسب للاختبار والتشغيل المحدود.
- التكلفة في الداشبورد تقدير باستخدام برنامج التغذية الحالي وأيام الشهر. الرسم المالي يعتمد على سجلات التحصيل، ولا يصطنع تاريخًا ماليًا. PDF تقرير خيل عربي مصور متعدد الصفحات، وExcel قابل للتحرير ويضم السجلات المتاحة للدور.
- حساب المالك يرى رسوم الإيواء المستحقة وسند التحصيل المفصل بعد السداد؛ المصروفات الداخلية لا تمنح له للقراءة العامة.
- الصورة الترحيبية توضيحية وليست صورة موثقة لإسطبل الأثيل. الشعار أصلي.
- لم تنقل بيانات المشروع القديم أو تنشر قواعد على قاعدته. يلزم ترحيل واختبار منفصل إذا اختيرت قاعدة قائمة؛ المصروفات القديمة لمرة واحدة تحتاج توزيعًا ثابتًا قبل التحصيل.

## البنية والتحقق

`src/` الواجهة العربية والاتصال والتقارير، `functions/src/domain.ts` قواعد العمليات المشتركة المختبرة، `functions/src/index.ts` الخدمات الموثوقة، `firestore.rules` صلاحيات القراءة ومنع الكتابة المباشرة، `android/` مشروع أندرويد، `tests/` اختبارات الإجراءات، و`docs/` تقرير المطابقة والاختبار.

البناء الآلي ينفذ الاختبارات، بناء الواجهة والخادم، ثم يبني APK تجريبيًا. لا ينشر Firebase ولا يرفع التطبيق إلى المتجر. اختبار دخول Google والخدمات على مشروع فعلي يبقى بعد توفير الإعدادات ونشر الخدمات.

مراجع الإعداد: [Capacitor Android](https://capacitorjs.com/docs/android)، [إعداد Google Sign-In](https://github.com/capawesome-team/capacitor-firebase/blob/main/packages/authentication/docs/setup-google.md).
